我想把寻找可参考 github 项目的任务交给你。

我的判断是：一定存在与我的预期重合度高、并且已经比较成熟的 github 项目。我希望直接参考这类项目，而不是从头开始造轮子。

当前问题是：

1. 我不知道哪些 github 项目值得参考。
2. 我不知道应该如何搜索这类项目。
3. 我需要你替我完成搜索、筛选和判断。

请按顺序执行：

1. 先根据我当前的预期，明确应该寻找哪类 github 项目。
2. 再设计搜索方式，说明你准备如何找到这些项目。
3. 然后实际搜索 github 项目。
4. 筛选出与我的预期重合度高、成熟度较高、值得参考的项目。
5. 对每个项目说明：
   - 它和我的预期哪里重合
   - 它为什么值得参考
   - 它哪些部分可以借鉴
   - 它哪些部分不适合直接照搬
6. 最后给出明确结论：我应该优先参考哪些项目，以及为什么。
- 完成第 1、2 步后，若当前工具支持子 Agent，且存在至少两条独立搜索路径，则通过只读子 Agent 并发分派检索；所有子 Agent 必须使用同一项目类型和筛选标准。
- 每个子 Agent 必须说明搜索方式、实际打开的仓库及相关文档/代码、重合点、可借鉴部分、不适合照搬部分和未满足筛选标准的证据；只返回项目名或搜索摘要不算完成验证。
- 第 4–6 步由你统一交叉比较、核验成熟度并裁定优先级，不得按推荐次数投票。

回答要求：

1. 不要只列项目名，必须说明筛选依据。
2. 不要因为某个项目看起来相关就直接推荐，必须判断它与我的预期是否真正重合。
3. 不要默认我要从头开发，重点是找到可参考、可改装、可提取有用部分的成熟项目。
4. 如果我的预期还不足以支撑准确筛选，先指出缺少哪些信息，不要强行推荐。

执行要求：质量是唯一目标，不考虑token成本、篇幅或速度。每个步骤必须实际执行，不许以推断代替验证，不许跳步，不许提前给结论。需要读的读完，需要查的查到，需要验证的验证后再继续。”
